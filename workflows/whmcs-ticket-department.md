# WHMCS Ticket Department Workflow

## Purpose
Step-by-step guide for changing ticket departments in WHMCS.

## Prerequisites
- Ticket exists
- Department change reason
- Authorization verified
- Departments configured

## Workflow Steps

### Step 1: Department Change Request
- Identify ticket
- Determine target department
- Document reason
- Verify authorization

### Step 2: Department Review
- List available departments
- Review department capabilities
- Check specialization
- Assess fit

### Step 3: Routing Assessment
- Evaluate routing needs
- Consider issue type
- Assess expertise required
- Determine best fit

### Step 4: Approval Process
- Route for approval (if needed)
- Verify authorization
- Document decision
- Set conditions

### Step 5: Handoff Preparation
- Prepare transfer details
- Document context
- List required information
- Set transfer timeline

### Step 6: Department Update
- Change ticket department
- Update routing
- Modify permissions
- Set department rules

### Step 7: Assignment Update
- Reassign ticket
- Route to appropriate queue
- Update workload
- Balance distribution

### Step 8: Notification
- Notify new department
- Inform previous owner
- Alert managers
- Update client (if applicable)

### Step 9: Client Communication
- Notify client (if applicable)
- Explain department change
- Provide new contact
- Set expectations

### Step 10: Documentation
- Log department change
- Record reason
- Document approval
- Update audit trail

## Department Change Reasons
- Wrong department
- Requires specialist
- Escalation
- Skill requirement
- Geographic routing

## Verification Checklist
- [ ] Department selected
- [ ] Approved
- [ ] Updated
- [ ] Assigned
- [ ] Notified
- [ ] Documented
